# type-clipboard 設計

- 日付: 2026-11-09
- 状態: 承認済み (作者が画面の動きの案を見て承認した)

## 1. 何を作るか

クリップボードの文字を、選んだ窓へキー入力として 1 文字ずつ打ち込む Windows のアプリ。

### なぜ

- 貼り付け (Ctrl+V) が効かない画面に、長いパスワードなどを打ち込みたい。
  - Hyper-V の仮想マシン接続 (VMConnect) の拡張セッションのサインイン画面。クリップボードの共有はサインインの後でないと効かず、基本セッションにある「クリップボードのテキストを入力」も拡張セッションには無い。
  - リモートデスクトップ (RDP) のサインイン画面。
  - ブラウザで開く VNC のコンソール (仮想化基盤やクラウドの管理画面)。
- パスワード管理アプリでコピーした 60 文字ほどの値を、手で打つのは現実的でない。
- 先に PowerShell の script (SendKeys で 1 文字ずつ打つ) で試し、VMConnect の拡張セッションのサインイン画面に打ち込めた。同じことを、打つ先を画面で選べるアプリにする。

### うまくいったと言える状態

- 打つ先の窓をアプリの中で選べ、選んでいる最中も選んだ後も、その窓の今の姿がアプリの中に映る。
- ボタン 1 つで、クリップボードの文字が打つ先へ打ち込まれる。
- 打つ先が前から外れたら、すぐに止まる。
- 単一の exe で、インストールなしで動く。CI (GitHub Actions) でビルドされる。

## 2. 目標にしないこと

- Enter を押す・フォームを送る。
- クリップボードの監視・履歴・自動で打つこと。ホットキーで打つこと (初版では作らない)。
- パスワードの保存、パスワード管理アプリとの連携。
- 管理者として動く窓への入力 (§5.1 の昇格した窓)。
- Windows 以外の OS。UI の多言語化 (日本語だけ)。
- インストーラ・自動更新・コード署名 (初版では作らない)。

## 3. してはいけないこと

- クリップボードの中身を、画面・ログ・ファイル・設定に出す・残す。
- 打つ先でない窓へ打つ。
- 打ち終わりに Enter を押す。
- public な repo に、作者の環境の固有の情報を載せる (§8)。

## 4. 画面と動き (承認済み)

1 つの窓に、上から次を並べる。

| 部品 | 中身 |
| --- | --- |
| 窓の一覧 | 打つ先の候補の窓。いつも見えている一覧にする (ドロップダウンは開くと下のプレビューが隠れるため使わない)。↻ で読み直すボタンと「クリックで選ぶ」ボタン |
| プレビュー | 候補か打つ先の窓の今の姿。左下に札 (「候補」は橙、「打つ先 ●」は青)。下に窓の題と exe の名前 |
| 打ち方 | 「キーの位置」/「文字 (Unicode)」のラジオボタン。配列 (日本語 (JIS) / 英語 (US))。1 文字ごとの間隔 (ms) |
| クリップボード | 文字数だけ (例: 「クリップボード: 60 文字」)。中身は出さない |
| ボタン | 「クリップボードを打つ」「試し打ち」 |
| 状態 | 状態の 1 行と、進み具合のバー |

動きの順:

1. 起こした直後: 打つ先は無く、プレビューは空。
2. 一覧をなぞる: なぞった窓が「候補」として映り、デスクトップの上でもその窓の周りに枠 (橙) が出る。
3. 「クリックで選ぶ」: 押した後は、マウスで指した窓が候補として映り、枠が付く。クリックはアプリが受け止め、相手の窓には届けない。Esc で取りやめる。
4. 決まる: 一覧で選ぶか、クリックで選ぶと、その窓が「打つ先」として映り続ける。決めた直後に枠 (青) を少しだけ出して消す。
5. 利用者が打つ先でパスワードの欄を出し、パスワード管理アプリで値をコピーする。アプリは文字数だけを出す。
6. 「クリップボードを打つ」: 打つ先を前に出し、1 文字ずつ打つ。進み具合 (n / N 文字とバー) だけを出す。
7. 打ち終わり: Enter は押さない。利用者が打つ先で押す。
8. 止まる: 打っている最中に、ほかの窓が前に来たら止める。利用者がキー (Esc を含む) を押したりクリックしたりしても止める。何文字打ったところで止めたかを出す。
   - 止めたわけ (ほかの窓・手で押したキー・ほかのアプリが送ったキー・クリック) も出す (2026-11-12 に書き足した。§5.3)。

## 5. 決めたこと

### 5.1 打つ先

- 打つ先は窓の題ではなく、窓そのもの (HWND) で覚える。題が変わる窓 (ブラウザなど) でも外れない。
- 一覧に出すのは、Alt+Tab に出るような top-level の窓 (見えている・題がある・ツールの窓でない・DWM で隠されていない (cloaked) もの)。アプリ自身は除く。
- 打つ先の窓が閉じたら、打つ先を外して、その旨を出す。
- 昇格した (管理者として動く) 窓は、打つ前に断る。UIPI で入力が届かないため。このアプリも管理者として起こせば打てる、と伝える。

### 5.2 プレビュー

- DWM のサムネイル (DwmRegisterThumbnail) で映す。タスクバーや Alt+Tab の縮小表示と同じ仕組みで、相手の窓が動いたまま映り、アプリは画素を持たない。GPU で描く窓 (ブラウザ・VMConnect) も映る。
- 縦横比を保って欄に収める。
- 最小化した窓は中身が描かれず、映らないことがある。そのときは欄にその旨を出す。

### 5.3 打ち方

- 打つ前に打つ先を前に出し (最小化されていれば戻し)、少し待ってから打ち始める (前の PowerShell の script では 500 ms)。前に出せなければ打たずに、その旨を出す。
- 1 文字ごとに、前面の窓が打つ先のままかを確かめる。違えば止める。
- 打っている最中に、利用者の手によるキー入力やクリック (アプリが送ったものでない入力) があれば止める。同じ窓の中でフォーカスが移ったこと (ブラウザのタブやアドレスバーへ移った) は窓の確かめでは見分けられず、パスワードが別の欄に入るおそれがあるため。
  - キーを打ち直す打つ先 (VMConnect) でも打てるよう、次のようにする (2026-11-12 に書き足した)。
    - VMConnect (Hyper-V の拡張セッション) は前にいる間、届いた修飾キー (少なくとも Shift と Ctrl) を自分の低レベルの hook でいったん握りつぶし、印 (`dwExtraInfo`) を 0x4321DCBA に付け替えて打ち直す。文字のキーは打ち直さない (試し打ちの見本 57 文字で、写しはすべて左 Shift だった)。写しは元と vk・scan・flags (拡張・離す) が同じで、元のすぐ後 (次の元より前) に来る。
    - その hook は VMConnect が前に来たときに入り、約 0.5 秒後に入れ直されることがあると見られる。前に来た直後 (10〜17 ms 後) と、そのとき (0.52〜0.54 秒後) に、文字を打たない合成のキー (vk 0xFF、`dwExtraInfo` 0x4321DCBA) も流れる。2 つ目の 0xFF は、0.6 秒以上見た 9 回のうち 5 回で出た (キーを送った回に多い)。
    - 前は「このアプリの印 (`INPUT_MARK`) の無いキーの押下とクリック」で止めていたので、待つ間に届く 0xFF と、送ったキーの写しで止まり、1 文字も打てなかった。
    - 打っている間の hook を 2 つの段で使い分ける。待つ段 (打つ先を前に出す前から、前に来て 500 ms 待ち終えるまで) は、手で押したキー (`LLKHF_INJECTED` が立っていない) の押下と手でしたクリック (`LLMHF_INJECTED` が立っていない) で止め、合成のキーは印が何でも通す。打つ段は、待ち終えて IME と修飾キーを確かめた後、1 文字を送る前に毎回、打つ thread が主窓に頼んで hook を入れ直してから、打ち終えるまで。
    - 入れ直すのは、Windows が後から入れた低レベルの hook から先に呼ぶため。VMConnect の hook より後に入れ直すと、このアプリの hook が元のキーを先に見て、写しを後に見る。前に来て 500 ms 待った後に 1 回だけ入れ直すと、VMConnect が約 0.5 秒後に hook を入れ直して先頭を取り返し、元のキーが見えずに写しだけが来て止まった (2026-11-12 の試作で 1 / 57)。1 文字ごとに入れ直すと、別の窓から前に出す流れで 3 回とも最後まで打てた。入れ直すと照らす覚えは消える。入れ直せなければ、そこで止める。
    - どちらの段でも、ほかのアプリが送った vk 0xFF (割り当ての無い仮想キー) は通す。文字を打たないので、通しても打つ値は変わらない。照らす覚えにも使わない。
    - 打つ段は、写しを照らして通す。このアプリの印のキーを通すときに、その形 (vk・scan・拡張・離す) を「直前の自分のキー」として覚える。印の違う合成のキーは、形が覚えと同じときだけ写しとして通し、覚えを消す (1 つの元に写しは 1 つまで)。写しが来ないまま次の自分のキーが来たら、覚えを置き換える (打ち直さない打つ先にもそのまま打てる)。形が覚えと違う・覚えが無い合成のキーの押下と、手で押したキーの押下は、止めて握りつぶす。キーを離す方は止めない。クリックは、このアプリの印でないものすべてで止める (このアプリはクリックを送らない)。
    - 覚える形は打つ文字から作る値なので、秘密専用のページに置き (§5.4 と同じく、物理メモリに留めて WER の dump から外す)、打ち終えたら (止めたときも) 上書きして消す。
    - 止めたわけは、手で押したキー・ほかのアプリが送ったキー (覚えが無いときと、形が覚えと違うときを分ける)・クリック・ほかの窓に分けて出す。キーの値は出さない。
    - 残る心配: 待つ段は、打つ先が先に打ち直す修飾キーを手で押しても、合成のキーと見て見落とす (打ち始める前に、修飾キーが押されたままでないかは確かめる)。入れ直してから送るまでの間に、打つ先やほかのアプリが hook を入れると、その文字の修飾キーは写しだけが届いて止まる。写しを変えて返す・遅れて返す打つ先でも止まる。どれも、違う値を黙って打つより止まる方に倒す。
- 「キーの位置」(既定): 文字を、選んだ配列でのキーの位置 (scancode) と Shift に直し、SendInput の KEYEVENTF_SCANCODE で送る。RDP・VMConnect・VNC は押したキーの位置を相手へ送り、相手の OS が自分の配列で文字に直すため。
  - 配列は、相手 (VM や接続先) の OS のキーボード配列に合わせて選ぶ。既定は英語 (US) で、設定に残した配列があればそれを使う。
    - 初めは「手元の Windows の今の配列」を既定にしていたが、2026-11-10 に作者の指示で英語 (US) に変えた。
  - 初版の配列は日本語 (JIS) と英語 (US)。
- 「文字 (Unicode)」: KEYEVENTF_UNICODE で文字そのものを送る。ふつうのアプリ向け。
- 打てない文字 (選んだ配列に無い文字・全角・絵文字など) を含むときは、打つ前に断る。どの文字かは出さず、数だけを出す。
  - 「文字 (Unicode)」の方式では全角や絵文字も打てるので、打てない文字は制御文字と壊れた UTF-16 (対の無い surrogate) だけにする (実装のときに書き足した)。
- 末尾の改行は落とす。途中に改行・タブを含むときは、打たずに断る (Enter・Tab を押すことになるため)。
- 1 文字ごとの間隔は既定 30 ms で、利用者が変えられる。
- 打ち始めに修飾キー (Shift・Ctrl・Alt・Win) が押されたままなら、打たずに断る。
- 「キーの位置」の方式のとき、CapsLock が on なら、打つ前に知らせて止める (大文字と小文字が逆になるため)。「文字 (Unicode)」の方式は CapsLock の影響を受けないので止めない (実装のときに書き足した)。
- 打つ先の窓で手元の IME がオンなら、打つ前に知らせて止める。IME が打った文字を変換し、違う値が黙って入るため。判定できない窓では止めない。
- 「試し打ち」: 決まった見本 (英字の大文字と小文字・数字・ASCII の記号の一通り) を打つ先へ打つ。配列が合っているかを、打つ先のテキスト欄で目で確かめるため。

### 5.4 クリップボード

- 文字 (CF_UNICODETEXT) を読み、文字数だけを出す。クリップボードが変わったという知らせを受けて数え直す。
- 中身は画面・ログ・設定に出さない。打ち終わったら (止めたときも) 手元の写しを消す。
- 写しが外 (ページファイル・クラッシュの dump・ログ) に残らないよう、次のようにする (2026-11-10 に書き足した)。
  - 文字数を数えるときも、打つ列を作るときも、このアプリのコードはクリップボードの中身を写さず、Windows が渡す中身をクリップボードを開いている間に読む (Windows がこのアプリのメモリに置く写しは、防げないものに挙げる)。
  - 打つ列 (打つ文字を、送るキーに直したもの) は、秘密専用にページ単位で確保したメモリ (VirtualAlloc) に置き、VirtualLock で物理メモリに留めて、ページファイルに書き出させない (Microsoft の文書は、留めている間はページファイルに書き出さないとしている)。ページをほかの確保と分け合わないので、ロックを外してもほかのロックは外れない。打ち終わったら (止めたとき・panic したときも) 上書きしてから、ロックを外して手放す。
  - 1 文字ずつの写しが乗る stack も物理メモリに留め、使い終えたら上書きする。打つ thread (送る INPUT の並びと UTF-16 の単位) は打つ間、UI の thread (打つ列を作るときに decode した文字と、打っている間に hook が受け取る、このアプリが送ったキー) は起動から閉じるまで留める。VirtualLock はロックを数えないので、1 つの thread で入れ子には留めない。
  - 打つ段の hook が写しと照らすために覚える直前のキーの形 (§5.3) も、打つ列と同じく秘密専用のページに置き、hook を外すときに上書きして消す (2026-11-12 に書き足した)。
  - 物理メモリに留められないときは打たない。打つ列を置けないとき (長すぎる文字など) と、打つ thread の stack を留められないときは打たずに断り、UI の thread の stack を留められないときは起動しない。パスワードの長さなら、作業セットの上限 (留められるページの数) には届かない。
  - クラッシュや応答なしで Windows のエラー報告 (WER) が dump を取るとき、heap を入れない (WerSetFlags の WER_FAULT_REPORTING_FLAG_NOHEAP)。起動のすぐ後に、このプロセスにだけ当てる。打つ列のページも、dump から外すよう登録する (WerRegisterExcludedMemoryBlock。このプロセスの中だけの登録)。レジストリなど、プロセスの外に残る設定は変えない。
  - 打つ thread が panic しても、打つ列を消し、hook を外して、その旨を出す (panic は unwind のままにし、打つ thread で受け止める)。知らせずに終わった打つ thread (外から止められたものも) は、主窓が見回って拾い、hook を外す。panic の文は標準エラーにも書かない。
  - 外へ書き出す書き方を足すと、clippy の lint で CI が止まる (§5.7)。
- このアプリでは防げないもの (2026-11-10 に書き足した):
  - 打つ先の側。受け取った文字の扱い (リモートの先の OS やアプリ)、途中の経路、ほかのアプリのキーボードの hook。
  - クリップボードそのもの。Windows が持つ中身、クリップボードの履歴 (Win+V)、ほかの端末との同期、クリップボードを読むほかのアプリ。
    - このアプリが読むたびに (クリップボードが変わって文字数を数え直すたびにも)、Windows がこのアプリのメモリ (heap) に中身の写しを置く (GetClipboardData)。この写しは、このアプリでは留めることも上書きすることもできず、ページファイルに書き出されうる。いつ手放されるかも Windows が決める。
  - 休止状態のファイル (hiberfil.sys) と、メモリ全体を書き出すもの (システムのクラッシュの完全なダンプなど)。物理メモリに留めたページも書き出される。
  - WER の dump に入る stack と register。heap を除いても入る。打っている最中にクラッシュすると、そのとき送っていた 1 文字ぶんの値 (打つ thread の INPUT の並び、UI の thread の hook が受け取ったキー) が入りうる。Rust の panic は受け止めるので、クラッシュは abort・アクセス違反・stack の溢れのときだけ。
  - 同じユーザーのほかのプロセス・管理者・デバッガ。このアプリのメモリを読め、dump も取れる。管理者が設定した dump の取り方 (WER の LocalDumps など) が heap を除くかも、このアプリでは決められない。外から止められた打つ thread の写しも消せない。
  - CPU の register と OS の側 (kernel) に一時的に乗る、1 文字ぶんの値。

### 5.5 設定

- 打ち方・配列・間隔・常に手前・窓の位置を %APPDATA% の下に残す。打つ先とクリップボードの中身は残さない。
- 「常に手前」のチェックを付ける (既定は on)。打っている間も進み具合が見えるようにするため。

### 5.6 作り

- Rust (stable)。Win32 は Microsoft の `windows` crate で直に呼ぶ。GUI も Win32 のネイティブのコントロールで組む。
  - 日本語は Windows の UI のフォントで出るので、フォントを同梱しなくてよい。
  - DWM のサムネイルは窓の上に重ねて描かれるので、自前で描く GUI (egui など) や WebView (Tauri) より、ネイティブのコントロールと組み合わせやすい。
- 単一の exe (x86_64-pc-windows-msvc)。console の窓は出さない。
- manifest で comctl32 v6 (見た目) と Per-Monitor V2 の DPI を有効にする。
- 文字から「キーの位置と Shift の列」への変換など、Win32 に触らない部分は分けて unit test を書く。

### 5.7 ビルドと CI

- GitHub Actions の windows-latest で、fmt の確認・clippy (warning を error に)・test・release ビルドを流す。
- PR と main の CI で、exe を workflow の成果物 (artifact) に上げる。merge の前に作者が試せるようにするため。
- tag (v*) を push したら、exe を GitHub Release に置く workflow を用意する。tag を打つのは作者で、初版の PR では打たない。
- Actions は commit の SHA で固定し、版をコメントで添える。GITHUB_TOKEN の権限は既定で contents: read にし、Release の job だけ contents: write にする。
- 手元 (WSL) からも nix flake の devShell で Windows の exe を作れるようにする (cross)。target と toolchain の取り方は作り手に任せる。
- 外へ書き出す書き方を、clippy の lint で deny にする (Cargo.toml の [lints.clippy] と clippy.toml。2026-11-10 に書き足した)。print_stdout・print_stderr・dbg_macro・use_debug (write! の Debug の書式。format! は見ない)・mem_forget (写しを上書きせずに残す)・disallowed_methods (標準出力と標準エラー・設定でないファイルへの書き込み (std と Win32)・OutputDebugString・RoOriginateError と windows::core::Error::new・ReportEvent・レジストリへの書き込み・プロセスを起こす・ネットワーク)・disallowed_macros (log と tracing の crate のマクロ)。要る所 (Windows でないときの main の 1 行・設定のファイルへの書き込み・決まった文を渡す Error::new) は、狭い #[expect] とわけで外す。依存の crate の中で書き出すものと、clippy.toml に無い API は止まらない。打つ文字と同じ値になる型 (Stroke・KeyStroke) の Debug は、中身を出さない。

### 5.8 ライセンスと文書
